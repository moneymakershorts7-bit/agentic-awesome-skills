# Mimic Pattern: Automated Application & Private API Reverse Engineering

The **Mimic Pattern** (popularized by `littledivy/mimic`) transforms dynamic application traffic into fully-typed, production-grade Python client SDKs without manual endpoint documentation.

---

## 1. Architecture Overview

```
┌─────────────────────────────────┐
│ Target App (iOS / Android / Web)│

                 │ (HTTPS / WSS / gRPC-Web)

┌─────────────────────────────────┐
│ Interception & Decryption Layer │ ◄── Frida Pinning Bypass (frida-server)
│ (mitmproxy / Proxyman / DevTools│
└────────────────┬────────────────┘
                 │ Raw Traffic Archive (.har / flows.dump / cURL)
```

## 2. Ingestion & Interception Recipes

### A. Headless mitmproxy Stream Recording
For automated interception in scripted or test environments:
```bash
# 1. Start mitmdump with flow capture to disk
mitmdump -p 8080 -w app_traffic.flows --set block_global=false

# 2. Or launch interactive web dashboard for selective inspection
mitmweb -p 8080 --web-port 8081 -w app_traffic.flows
```

### B. Mobile TLS Pinning Defeat (Phase 3 Integration)
Target apps using certificate pinning reject proxy CAs. Bypass via Frida DBI:
```bash
# Android (Universal OkHttp / TrustManager bypass)
frida -U -f com.target.app -l /path/to/universal-ssl-pinning-bypass.js

# iOS (Security framework SecTrustEvaluate bypass)
frida -U -f com.target.app -l /path/to/ios-ssl-bypass.js
```

### C. Browser DevTools / Proxyman HAR Export
From Chrome/Firefox DevTools:
1. Open **Network** tab -> Check **Preserve log**.
2. Exercise user workflow in the web application.
3. Right-click any request -> **Save all as HAR with content** -> `session.har`.

## 3. Automated SDK Synthesis with Mimic

### A. CLI Commands
```bash
# Generate directly from mitmproxy flows
uvx mimic==0.1.0 capture --mitmproxy

# Generate client SDK from exported HAR file
uvx mimic==0.1.0 generate --har session.har -o ./generated_client/

# Inspect or generate from raw cURL script
uvx mimic==0.1.0 generate --curl curl_dump.sh -o ./generated_client/
```

### B. Python API Pattern
When integrating directly into automated agent workflows:
```python
from mimic import Session

# Ingest recorded HAR session
session = Session.from_har("session.har")

# Synthesize client code targeting httpx and pydantic
client_code = session.generate_client(
    client_name="TargetAPIClient",
    async_enabled=True,
    pydantic_v2=True
)

with open("client.py", "w") as f:
    f.write(client_code)
```

## 4. Generated Client Structure Standard

A properly synthesized Mimic client adheres to clean-room engineering standards:

```
generated_client/
├── __init__.py          # Exports TargetAPIClient and Model classes
├── client.py            # Primary httpx.AsyncClient / Client wrapper
├── models.py            # Pydantic v2 BaseModel request/response schemas
├── auth.py              # AuthHandler (Bearer, HMAC signature, Session refresh)
└── exceptions.py        # Typed API exceptions mapped to HTTP status codes
```

### Example Synthesized Interface
```python
# Generated by reverse-engineering-super (Mimic Engine)
from typing import Optional, List
from pydantic import BaseModel, Field
import httpx

class UserProfile(BaseModel):
    id: str
    username: str
    is_active: bool
    roles: List[str] = Field(default_factory=list)

class TargetAPIClient:
    def __init__(self, token: str, base_url: str = "https://api.example.com/v1"):
        self.base_url = base_url
        self.client = httpx.Client(
            base_url=base_url,
            headers={
                "Authorization": f"Bearer {token}",
                "User-Agent": "TargetApp/2.4.0 (iOS 17.4)",
                "Accept": "application/json"
            }
        )

    def get_profile(self, user_id: str) -> UserProfile:
        resp = self.client.get(f"/users/{user_id}")
        resp.raise_for_status()
        return UserProfile.model_validate(resp.json())
```

## 5. Defensive & Safety Invariants

1. **Zero Credential Hardcoding:** Generated code must parameterize all tokens and session secrets as arguments or environment variables (`os.getenv("API_TOKEN")`).
2. **Defensive Interoperability Scope:** Intended solely for private API documentation, legacy backend migration, and interoperable client creation.
3. **No Attack Payloads:** Request body fuzzing or injection automation is strictly barred.
